# ADR-001. Фиксированные многошаговые маршруты с общими инструментами

| Поле | Значение |
|---|---|
| Статус | Принято для прототипа КТ3 |
| Дата | 22.11.2026 |
| Авторы | Команда проекта |
| Связано | [Архитектура и харнесс](../design-doc.md#4-архитектура-решения), [отчёт](../kt3/results.json) |

## Контекст

Система отвечает на вопросы по SQL и версиям документов. Когда вопрос связан с релизом, дата из документа должна определять границы SQL-запроса. При отказе инструмента или исчерпании бюджета статусы и подтверждённая часть ответа должны быть воспроизводимы. На КТ3 доступен фиксированный синтетический корпус и локальный запуск. Целевое время ответа для сложного случая составляет 60 секунд, бюджет модели — $0.05.

## Варианты

| Вариант | Качество | Задержка и стоимость | Почему не выбран или выбран |
|---|---|---|---|
| Один маршрут по простым правилам | Обрабатывает часть прямых вопросов и не покрывает зависимый поиск после SQL | По результатам baseline, P95 около 111 мс и нулевые вызовы модели | Оставлен как baseline, сценарии КТ3 прошёл 1 из 6 |
| Фиксированные цепочки параметризованных инструментов | Передают между шагами наблюдаемые даты, строки и ссылки на документы. Покрытие ограничено каталогом маршрутов | P95 около 105 мс, вызовов модели нет | Выбран для КТ3, пройдены 6 из 6 сценариев |
| LLM-планировщик с теми же ограниченными инструментами | Может распознавать новые формулировки. Возможны лишние вызовы и ошибки планирования | Нужны бюджет токенов, замеры API и отдельные проверки | Отложен до эксперимента на тех же вопросах, поскольку эффект и расходы ещё не измерены |

## Решение

Используем фиксированные цепочки для зависимых сценариев и общий интерфейс исполнения с baseline. Только SQL-шаблоны из каталога доступны инструменту. Ограничиваем выполнение шестью вызовами на реплику, включая повторы. В отказах возвращаем подтверждённую часть, когда она есть, и записываем причину остановки.

## Последствия

Локальный запуск повторяется без ключей API. На видимом наборе совпадение статуса выросло с 87/135 до 105/135, а число совпавших SQL-шагов — с 45/90 до 60/90. Проверка полноты и подтверждённости свободного ответа требует разметчика. Маршруты необходимо дополнять при появлении новых задач.

Пересмотрим выбор в пользу LLM-маршрутизатора, если он на замороженном наборе повысит покрытие и подтверждённость, сохранит нулевое число нарушений прав и уложится в бюджет. Один простой маршрут будет достаточен, если трафик реального пилота окажется преимущественно прямым и на связанных задачах оператор будет получать нужный результат из заранее подготовленного отчёта.
